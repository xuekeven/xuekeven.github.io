TS 和 JS 区别

TS 是 JS 的超集，可以被编译成 JS 代码。用 JS 编写的代码在 TS 中依然有效。TS 是纯面向对象的编程语言，包含类和接口的概念。 程序员可以用它来编写面向对象的服务端或客户端程序，并将它们编译成 JS 代码。

为什么使用 TS

  • 类型系统：提供静态类型检查，在编译阶段发现错误，提升代码可靠性
  • 更好的 IDE 支持：智能提示、跳转、重构更准确，提高开发效率
  • 增强的可维护性：类型约束让代码更易于理解和维护，尤其适合大型项目
  • 现代特性支持：支持 ES6+ 语法和特性（类、模块、泛型、装饰器等）
  • 与 JS 兼容：TS 是 JS 的超集，现有 JS 项目可以渐进迁移，不会有断层

any 和 unknown 区别

any 和 unknown 都能接收任意类型的值，但 any 会完全关闭类型检查，可以随便用，非常不安全；unknown 更安全，它要求我们在使用之前必须做类型缩小。通常情况下，如果不确定类型，推荐用 unknown 而不是 any。

特性 any unknown
类型检查 不做检查 必须先检查才能使用
安全性 低（可能埋雷） 高（强制开发者做类型守卫）
赋值 可以赋值给任何类型 只能赋值给 any 或 unknown
使用场景 快速原型、临时绕过类型 接口数据不确定、需要后续收窄类型

TS 支持的访问修饰符

TypeScript 在类中支持 public、private、protected 三种访问修饰符。默认是 public，表示对外公开；private 表示成员只能在类的内部访问；protected 表示成员只能在类和子类中访问。还有 readonly（只读属性）和 static（静态成员）修饰符，用来增强类的封装性和可维护性。

declare 关键字作用

declare 关键字在 TS 中用来声明已经存在的变量、函数、类、模块等，不需要在 TS 文件中实现。它只在编译时生效，不会生成运行时代码。常见场景：

  • 声明全局变量/函数/类
  • 声明第三方库的类型
  • 写 .d.ts 类型声明文件

类型断言是什么

类型断言可以用于手动指定一个值的具体类型，即允许变量从一种类型更改为另一种类型。

命名空间与模块区别

命名空间主要用于全局作用域下的组织代码，防止命名冲突，而模块是基于文件的作用域隔离机制，通过 import/export 实现代码复用。随着 ES6 模块的普及，更推荐使用模块而不是命名空间。

对比点 命名空间（Namespace） 模块（Module）
定义方式 namespace 关键字 一个文件就是一个模块
导入导出 export 导出，在同一文件或全局作用域使用 使用 export / import
使用场景 早期全局作用域代码组织，解决命名冲突 现代前端/Node.js 工程化开发
作用域 命名空间是全局的，容易被打包进一个文件 模块有自己作用域，天然隔离
推荐程度 不推荐（过时，适合小项目/老项目） 强烈推荐（符合 ES6 标准）

tsconfig.json

在 tsconfig.json 文件中，可以指定不同的选项来告诉编译器如何编译当前项目。目录中包含 tsconfig.json 文件，表明该目录是 TypeScript 项目的根目录。
