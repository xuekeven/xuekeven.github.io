概念

原因

为了提高网页的加载速度和响应速度，给用户带来更好的体验和用户满意度，同时还能减少服务器的负载压力，以此来提升程序的稳定性，具体有以下几个因素：

  • 提高用户体验
  • 提高用户留存率
  • 提高搜索引擎排名
  • 增加页面访问量
  • 减少服务器压力
  • 节约成本

LCP

LCP（Largest Contentful Paint，最大内容渲染时间）

  • 含义：测量视口中最大文本或图片元素完成渲染的时间（例如首屏横幅图或标题）
  • 理想值：≤ 2.5 秒（超过 4 秒为“差”）
  • 影响因素：
    • 服务器响应慢（TTFB 高）
    • 渲染阻塞的 JS/CSS 文件
    • 未优化的图片/视频资源
  • 优化方向：
    • 预加载关键图片：<link rel="preload" as="image" href="banner.jpg">
    • 开启 HTTP/2 或 CDN 加速资源传输
    • 服务端渲染（SSR）减少客户端渲染延迟

FCP

FCP（First Contentful Paint，首次内容绘制时间）

  • 含义：记录浏览器首次渲染任何内容的时间（如文字、图片），标志着用户感知到页面开始加载
  • 理想值：≤ 1.8 秒（超过 3 秒为“差”）
  • 与 LCP 区别：FCP 关注“首次开始渲染”，LCP 关注“最大内容渲染完成”
  • 优化方向：
    • 内联关键 CSS（Critical CSS）
    • 异步加载非阻塞 JS（async/defer）
    • 减少首屏 DOM 复杂度

FID

FID（First Input Delay，首次输入延迟）

  • 含义：测量用户首次交互（点击按钮、输入文本）到浏览器实际响应的时间，反映页面可交互性
  • 理想值：≤ 100 毫秒（超过 300 毫秒为“差”）
  • 根本原因：主线程被长任务（Long Tasks >50ms）阻塞（如解析大 JS 文件）
  • 优化方向：
    • 拆分长任务：用 requestIdleCallback 分片执行
    • 优化第三方脚本（广告、分析工具）
    • 使用 Web Workers 处理计算任务

CLS

CLS（Cumulative Layout Shift，累积布局偏移）

  • 含义：量化页面意外布局移动的严重程度（例如图片加载后挤压下方内容）
  • 计算方式：CLS = 影响比例 × 位移距离（视口高度占比）
  • 理想值：≤ 0.1（超过 0.25 为“差”）
  • 常见场景：
    • 未设置尺寸的图片/广告位
    • 动态插入的页面元素（如弹窗）
    • 异步加载的字体 37。
  • 优化方向：
    • 为媒体元素设置宽高：<img width="600" height="400" src="...">
    • 预留动态内容占位区域
    • 使用 transform: scale() 替代改变布局的属性

方案

从优化目标、优化策略两个方面来考虑。还可以了解一下六大指标。

优化目标

分为时间层面和体积层面。

加载性能

  • 目标：LCP ≤2.5s（首屏内容渲染）、FCP ≤1.8s（首次内容绘制）
  • 策略：资源压缩、CDN 分发、预加载关键资源

交互体验

  • 目标：FID ≤100ms（输入响应）、CLS ≤0.1（布局稳定性）
  • 策略：拆分长任务、避免强制同步布局、使用 will-change 触发 GPU 加速

资源效率

  • 目标：JS <200KB（首屏）、CSS <100KB、图片体积减少 25%-50%
  • 策略：Tree Shaking、图片转 WebP/AVIF、字体子集化

优化策略

分为网络传输、页面解析渲染、运行时性能。

网络传输

  • 构建策略

    • 合并小文件，减少 HTTP 请求
    • 使用 GZIP 压缩静态文件（HTML/CSS/JS/图片）
    • JS Tree Shaking
    • CSS Tree Shaking
    • 按需加载（懒加载）
    • 择优选择三方库依赖

  • 图片优化/图像策略

    • 用 CSS 代替图片
    • 图片延迟加载
    • 响应式图片
    • 调整图片大小
    • 降低图片质量
    • 使用 webp 格式

  • 请求策略

    • 减少 Cookie 传输
    • 使用 HTTP2

  • 分发策略

    • 静态资源使用 CDN

  • 缓存策略

    • 使用 HTTP 缓存

页面解析渲染

  • DOM 策略

    • 尽量减少 DOM 数量
    • 缓存 DOM 计算属性
    • 避免过多 DOM 操作
    • 使用 DOMFragment 缓存批量化 DOM 操作

  • CSS 策略

    • 避免为 ID 选择器添加多余选择器
    • 避免使用标签选择器代替类选择器
    • 避免使用通配选择器，只对目标节点声明规则
    • 避免重复匹配重复定义，关注可继承属性
    • 尽量降低 CSS 选择器复杂度
    • 尽量用link少用@import
    • 尽量用 CSS 实现动画
    • 使用 transform 和 opacity 实现动画
    • 使用弹性布局

  • 阻塞策略

    • 使用骨架屏
    • 静态生成首屏文件
    • 使用服务端渲染（SSR）
    • 尽量减少 JS 操作 DOM 和 CSSOM
    • CSS 文件放在头部，JS 文件放在底部或使用 defer/async

  • 回流重绘策略

    • 减少使用会导致回流的属性和方法
    • 减少使用会导致重绘的属性和方法

运行时性能

  • JavaScript 执行性能

    • 事件节流/防抖（throttle / debounce）
    • 启用事件委托
    • if-else 对比 switch
    • 使用位操作
    • 尽量使用原生方法，执行效率高
    • 虚拟列表（virtual scroll）

  • 内存管理

    • 及时清理定时器和事件监听
    • 避免内存泄漏（闭包/DOM 引用未释放）

  • 使用 Web Worker

    • 耗时计算放到 Worker 中，避免阻塞 UI

  • React

    • 使用 hook 添加依赖
    • 使用 memo 函数

  • Vue

    • 合理使用 watch 和 computed，数据变化就会执行，避免使用太多，减少不必要的开销
    • 合理使用组件，提高代码可维护性的同事也会降低代码组件的耦合性
    • 使用路由懒加载，在需要的时候才会进行加载，避免一次性加载太多路由，导致页面阻塞
    • 使用 Vuex 缓存数据
    • 合理使用 mixins，抽离公共代码封装成模块，避免重复代码。
    • 合理使用 v-if 、v-show
    • v-for 不要和 v-if 一起使用，v-for 的优先级会比 v-if 高
    • v-for 中不要用 index 做 key，要保证 key 的唯一性
    • 使用异步组件，避免一次性加载太多组件
    • 避免使用 v-html，存在安全问风险和性能问题，可以使用 v-text
    • 使用 keep-alive 缓存组件，避免组件重复加载
